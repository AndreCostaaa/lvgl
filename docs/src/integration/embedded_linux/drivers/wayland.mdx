## Overview

The Wayland [driver](https://github.com/lvgl/lvgl/tree/master/src/drivers/wayland) renders LVGL into a
Wayland surface and reads keyboard, pointer and touch input from the compositor. It suits production
deployments — kiosk interfaces, control panels, and other embedded GUIs on systems that already run a
Wayland compositor — and is equally useful for development on a Linux desktop, as an alternative to the
[X11](/integration/embedded_linux/drivers/X11) and [SDL](/integration/pc/sdl) drivers.

The driver offers three rendering backends: **SHM** (shared memory, the default), **EGL** (OpenGL ES) and
**G2D** (NXP i.MX 2D accelerator). Which one you pick determines whether frames are produced by the CPU or
by hardware; everything else about the driver stays the same.

## Configuration

Enable <ApiLink name="LV_USE_WAYLAND" />, and set <ApiLink name="LV_COLOR_DEPTH" /> to `32` or `16`.

Enabling the driver is also what pulls the Wayland client libraries into the build — LVGL's CMake
integration resolves `wayland-client`, `wayland-cursor` and `xkbcommon` for you, so there is nothing to link
by hand. None of them can be built from source by LVGL, so they must already exist on the system or in your
sysroot. See [Dependency Management](/integration/building/cmake) for how resolution works and how to steer
it.

The driver also needs Wayland protocol bindings generated by `wayland-scanner`, which LVGL's CMake
integration runs for you: `xdg-shell` always, and `linux-dmabuf-v1` when a backend needs it. The protocol
XML is looked up under `$SDKTARGETSYSROOT`/`$SYSROOT`/`/usr/share/wayland-protocols`.

### Selecting a rendering backend

Set `LV_WAYLAND_BACKEND` to one of:

| Value | Backend |
|---|---|
| `LV_WAYLAND_BACKEND_SHM` | Shared memory via `wl_shm` (default) |
| `LV_WAYLAND_BACKEND_EGL` | OpenGL ES via EGL |
| `LV_WAYLAND_BACKEND_G2D` | NXP i.MX G2D accelerator |

<Callout type="warning" title="Turn off the legacy auto-backend first">
`LV_WAYLAND_BACKEND` is only honoured when `LV_WAYLAND_AUTO_BACKEND` is `0`. Auto mode is the legacy
behaviour and is still the default when you configure LVGL without Kconfig: it forces SHM and honours the
deprecated `LV_WAYLAND_USE_SHM` / `LV_WAYLAND_USE_EGL` / `LV_WAYLAND_USE_G2D` symbols instead. Set
`LV_WAYLAND_AUTO_BACKEND` to `0` whenever you select a backend explicitly. Auto mode is slated for removal.
</Callout>

Each accelerated backend needs one companion symbol. Kconfig selects it automatically; if you configure
LVGL through a config header you have to enable it yourself.

| Backend | Also needs | Extra libraries |
|---|---|---|
| `LV_WAYLAND_BACKEND_EGL` | <ApiLink name="LV_USE_OPENGLES" /> — a build error is raised if it is missing | `wayland-egl` |
| `LV_WAYLAND_BACKEND_G2D` | <ApiLink name="LV_USE_DRAW_G2D" /> | `g2d`, `libdrm` |

<Callout type="info">
`LV_USE_G2D` is deprecated and has no effect. The G2D backend is driven entirely by
<ApiLink name="LV_USE_DRAW_G2D" />.
</Callout>

The EGL backend drives EGL through <ApiLink name="LV_USE_EGL" />, which LVGL derives from the backend
choice — do not set it by hand.

### Other options

| Symbol | Default | Effect |
|---|---|---|
| `LV_WAYLAND_DIRECT_EXIT` | on | Deinitialize LVGL and exit once the last window closes. Turn it off to handle window closure yourself. |

## Usage

[lv_port_linux](https://github.com/lvgl/lv_port_linux) is the reference project — it carries a working CMake
setup for the Wayland driver, including protocol generation, for every backend. Start from it rather than
assembling the build yourself.

<ApiLink name="lv_wayland_window_create" /> opens a window and returns its display. Pass a close callback if
you want to track when the user dismisses it.

```c
#define H_RES 800
#define V_RES 480

lv_display_t * disp = lv_wayland_window_create(H_RES, V_RES, "Window Title", close_cb);
```

Call it again to open more windows; each gets its own display and its own set of input devices.

### Input devices

Each window registers four input devices, wired to the corresponding Wayland events:

| Device | Wayland source | Getter |
|---|---|---|
| KEYPAD | keyboard | <ApiLink name="lv_wayland_get_keyboard" /> |
| POINTER | touch | <ApiLink name="lv_wayland_get_touchscreen" /> |
| POINTER | pointer | <ApiLink name="lv_wayland_get_pointer" /> |
| ENCODER | pointer axis (scroll) | <ApiLink name="lv_wayland_get_pointeraxis" /> |

<Callout type="warning" title="Check the display before querying input devices">
The getters return `NULL` if called before the display is fully initialised. Always check that the display
returned by <ApiLink name="lv_wayland_window_create" /> is non-`NULL` first.
</Callout>

To enable keyboard and encoder navigation, put the relevant devices in a group:

```c
/* Create a group and set it as default */
lv_group_t * g = lv_group_create();
lv_group_set_default(g);

/* Assign keyboard and encoder to the group */
lv_indev_set_group(lv_wayland_get_keyboard(disp), g);
lv_indev_set_group(lv_wayland_get_pointeraxis(disp), g);
```

Once a group is the default, every focusable widget created afterwards joins it automatically, so arrow keys
and encoder rotation move focus and Enter activates.

### Window state

| Function | Purpose |
|---|---|
| <ApiLink name="lv_wayland_window_set_fullscreen" /> | Enter or leave fullscreen |
| <ApiLink name="lv_wayland_window_set_maximized" /> | Maximize or restore |
| <ApiLink name="lv_wayland_window_set_minimized" /> | Minimize |
| <ApiLink name="lv_wayland_window_close" /> | Close the window |
| <ApiLink name="lv_wayland_window_is_open" /> | Test whether it is still open |

With multiple physical displays, assign the window to one before going fullscreen so it appears where you
want it:

```c
/* Assign to physical display 0 and go fullscreen there */
lv_wayland_assign_physical_display(disp, 0);
lv_wayland_window_set_fullscreen(disp, true);
```

<ApiLink name="lv_wayland_unassign_physical_display" /> restores the default behaviour.

If you integrate LVGL into your own event loop, <ApiLink name="lv_wayland_get_fd" /> gives you the
compositor's file descriptor to poll.

## Rendering Backends

### SHM (default)

Renders into `wl_shm` shared-memory buffers. Works on every Wayland compositor and needs no particular
hardware, at the cost of CPU blitting.

Rotation is handled in software. At rotation 0 LVGL renders straight into the mapped compositor buffers;
when rotation is not 0 the backend allocates an extra full-frame buffer and rotates into it, so each frame
costs one additional full-screen copy.

### EGL

Renders through OpenGL ES 2.0 and EGL, and is the backend to use with LVGL's GPU draw units and
[3D/glTF content](/integration/embedded_linux/opengl). Rotation is done by the GPU at no extra copy.

Requires OpenGL ES 2.0 on the target and the `wayland-egl` library.

#### DMA-BUF fast path

When the EGL backend is selected but **no GPU draw unit** is enabled — neither
<ApiLink name="LV_USE_DRAW_NANOVG" /> nor <ApiLink name="LV_USE_DRAW_OPENGLES" /> — LVGL still renders in
software, and the EGL backend presents those frames through the `zwp_linux_dmabuf_v1` protocol instead of
copying them. On platforms with zero-copy buffer sharing this is measurably faster than the classic path,
and the backend falls back to the classic path automatically when the support is missing.

This is derived, not configured: LVGL turns on `LV_WAYLAND_USE_DMABUF` for you and adds `libdrm` and `gbm`
to the build. Enabling a GPU draw unit turns the fast path off, because rendering then happens on the GPU
and there is nothing to blit.

Requirements, all handled by LVGL's CMake integration:

- A compositor advertising `zwp_linux_dmabuf_v1`, and a GPU/display driver that supports DMA-BUF
- `libdrm` and `gbm`, used to allocate the shared buffers
- The `linux-dmabuf-v1` protocol bindings, generated at build time

### G2D

Uses NXP's G2D 2D accelerator, available on i.MX 6 and i.MX 8 parts, for hardware-accelerated blits and
rotation, presenting frames through DMA-BUF. It needs the `g2d` library on the system and enables the
[G2D draw unit](/integration/chip_vendors/nxp/g2d_gpu) alongside the display path.

## Window Decorations

<Callout type="info">
As of LVGL v9.5 the `LV_WAYLAND_WINDOW_DECORATIONS` option has been removed. Setting it produces a build
warning.
</Callout>

Title bars, borders and close buttons are now the application's responsibility. Build them from LVGL
widgets — the [Window (lv_win)](/widgets/win) widget gives you a title bar with buttons, or you can compose
your own from containers, labels and buttons. Fullscreen and kiosk applications simply omit them.

## Support

| Capability | SHM | EGL | G2D |
|---|---|---|---|
| Rotation | Software (extra full-frame copy) | Hardware (GPU) | Hardware (G2D) |
| Runtime resolution change | Yes | Yes | Yes |
| Runtime color format change | Yes | Yes | Yes |
| Color formats | RGB565, XRGB8888, ARGB8888 | RGB565 or ARGB8888, from <ApiLink name="LV_COLOR_DEPTH" /> | RGB565, XRGB8888, ARGB8888 |
| Multiple displays / windows | Yes | Yes | Yes |
| Hardware acceleration | None | OpenGL ES | NXP G2D |
| Render mode | Direct — fixed | Full with NanoVG, otherwise Direct — fixed | Direct — fixed |
| Input | Built in — keyboard, pointer, touch, encoder per window | Built in | Built in |

The compositor owns the buffers on every Wayland backend, so the render mode is fixed by the driver — there
is no knob to turn. The G2D backend falls back to XRGB8888 when the hardware cannot do RGB565.

## Reporting Bugs

The Wayland driver is under active development; bug reports and feedback are welcome. Detailed issues help
most — enable <ApiLink name="LV_USE_LOG" /> and capture both LVGL's log and the Wayland message stream:

```sh
WAYLAND_DEBUG=1 ./path/to/executable > /tmp/debug 2>&1
```

Attach `/tmp/debug` to the issue. Reproduce the problem quickly, otherwise the log grows unwieldy.
