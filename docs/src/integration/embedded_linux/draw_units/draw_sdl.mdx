## Overview

The SDL draw unit renders widgets in software, caches the result as an SDL texture, and lets SDL's own
renderer blend those textures into the final frame. It is a hybrid: software rasterization,
hardware compositing.

It is the natural choice when your application already uses SDL and you want cheap acceleration without
introducing an OpenGL dependency. It works best with static or slowly-changing UIs, where most textures are
reused between frames, and offers little for content that changes every frame.

For genuinely GPU-accelerated rendering, use [NanoVG](/integration/embedded_linux/draw_units/draw_nanovg)
through the SDL driver's EGL backend instead — it rasterizes on the GPU rather than only compositing there.

## Configuration

Enable <ApiLink name="LV_USE_DRAW_SDL" /> alongside <ApiLink name="LV_USE_SDL" />. It has no options of its
own.

Selecting `LV_SDL_BACKEND_TEXTURE` in the SDL driver enables this draw unit for you, so on Kconfig-configured
builds picking the backend is enough. Rasterization still happens in software, so keep the software renderer
(<ApiLink name="LV_USE_DRAW_SW" />, on by default) enabled.

Enabling <ApiLink name="LV_USE_DRAW_SDL" /> is also what pulls `SDL2_image` into the build. Unlike most Linux
display dependencies it **can** be fetched and built from source by LVGL if it is not installed. See
[Dependency Management](/integration/building/cmake).

## Support

The draw unit and the SDL driver's texture backend are two halves of the same thing, and the backend fixes the
render mode to full — there is no knob to turn.

<Callout type="info" title="LV_SDL_RENDER_MODE does not apply here">
`LV_SDL_RENDER_MODE` is honoured only by the SDL driver's *software* backend. The texture and EGL backends
override it, so setting it has no effect once this draw unit is in use.
</Callout>
